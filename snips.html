Snips AI Assistant

0→1 AI-powered content tracking - exploring new use cases for desktop power users

Currently in beta

Challenge

The founder and CEO wanted to explore browsing use cases beyond privacy, building on Aloha's existing infrastructure. With AI becoming increasingly relevant, they saw an opportunity to add value for desktop and iOS power users. This was an innovation push - market exploration to see if we could capture desktop users and expand our product offering. Engineering built an MVP that showed sufficient user signal. I was brought in to take it to the next level.

Innovation Goal

Explore AI-powered tracking use cases

Expand desktop offering beyond privacy

Build potential cloud service foundation

MVP Limitations

Bare-bones UI and dated visual design

Capture frames looked like screenshots

No visual feedback for snip updates

Design Challenges

Polish MVP for beta testing appeal

Make AI behavior trustworthy for privacy-focused users

Balance flexibility (diverse use cases) with simplicity

My Role

I joined the project after engineering built an MVP that showed sufficient user signal to invest further. I reported to the Founder (acting as product lead) and Design Lead, working closely with Desktop engineering lead and iOS developer.

I owned the UI, UX, and feature roadmap. I pitched how web services should work and collaborated across the company on use case exploration - people tested the product internally and reported back. The tracking mechanics were a team effort informed by early user interviews.

This project required more autonomy and less direction than typical feature work. Because product vision and validation were shallow, it was hard to define what this should be. But I understood the technical direction and potential, so I shaped what needed to be done.

Solution

Hybrid AI Prompts

Built both natural language and structured prompts. The AI model detects keywords on pages and suggests structured prompts, but users can modify or write their own.

For shopping pages: users preferred suggested templates. For complex tracking: users modified prompts for specificity.

User Control Over AI

Clear feedback when AI processes requests

Users control notification timing

Users define which page area to track

Organization System

Designed groups and categorization - testing showed users tracked 5-10+ items simultaneously.

Redesigning the Capture System

The MVP's capture frames looked like screenshots, misdirecting users about functionality. I redesigned the capture experience with distinct visual identity and clear tracking indicators, so users understood they were creating live tracking instances, not saving static images.

Market Insights

We proved there are use cases where this product works for users, primarily in shopping. However, wider release hasn't happened yet. The product is still in exploration phase - validating technical feasibility and user interest before committing to full launch and potential web service infrastructure.

Key Learnings

Balancing flexibility and simplicity

The product needed to handle diverse use cases (shopping, flights, visa queues) without becoming complex. The hybrid prompt approach - structured suggestions with natural language fallback - solved this by adapting to context.

0→1 scope is fundamentally different

The breadth of scope and potential in new products is different from normal features. There's no clear "success metric" yet - you're proving feasibility and exploring market fit simultaneously.

Working in ambiguity requires judgment

Looking at use cases and working through edge cases was paramount to achieving coherent direction. This is fundamentally different from optimizing existing features with clear metrics.
